| BN6's wait for a frame (`src/emu/idle.c`, issue #35) | `0x080003A0` main_awaitFrame, its loop at `0x080003A6`; DISPSTAT `0x04000004`, IE `0x04000200`, IME `0x04000208` | bn6f `main_awaitFrame`, at the same address in Gregar: `ldr r0,=0x04000004; movs r2,#1`, then the loop `ldrh r1,[r0]; tst r1,r2; beq` (`0x080003A6`-`0x080003AA`) until DISPSTAT's VBlank flag is set; then the VBlank count at `0x0200A870` against `0x02009930`, back to the start while short, and the count zeroed. Found by sampling the PC every 1000 GBA cycles: 48% of a layer's cycles and 57% of a battle's in that 16-byte span. mGBA does not take it for an idle loop: its `GBAIORead` clears `haltPending` on any register read but a constant one, and DISPSTAT is not one (`src/gba/io.c`). The hook (`BN6_AWAIT_FRAME_LOOP`) halts the CPU there while DISPSTAT's VBlank flag (bit 0) is clear and its interrupt is on (DISPSTAT bit 3, IE bit 0, IME bit 0), so the VBlank interrupt ends the halt by the time the flag would end the loop. Verify: the autopilot's debug log and run log are the same with and without it, and `CYBERWORLD_EMU_DEBUG`'s 30-frame line counts about four more hook hits a frame (each interrupt that wakes the CPU before VBlank brings it back to the loop). |
