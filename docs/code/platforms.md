# The platforms and their packaging

| Path | Contents |
| --- | --- |
| `port/` | The PortMaster port: the launcher, `port.json`, `gameinfo.xml` and the README of PortMaster-New's `ports/cyberworld/`; `build.py package` puts them in that folder's layout in `build/port/cyberworld/`, with the screenshot (`docs/screenshots/portmaster.png`), the binary and one `licenses/LICENSE.<part>.txt` per part |
| `linux/` | The Linux release: its README, the tar.gz's menu installer, the `.desktop` entry, AppStream metadata and the icons (`tools/app_icon.py`) that the AppImage, the `.deb` and the Flatpak (`linux/flatpak/`: its manifest, how to build it and bring it to Flathub) carry. The app ID `io.github.saschb2b.Mega-Man-Battle-Network-Cyberworld-Endless` is the window's class too (`src/core/platform.h`); `src/core/desktop.c` finds the ROM, opens the file chooser for the ROMs screen (`zenity`, `kdialog`, `osascript`) and adds the AppImage to the menu. `linux/steam/`: `add-to-steam.py` (the game as a non-Steam shortcut, with the library artwork `tools/steam_art.py` draws), which every Linux build carries and `--add-to-steam` runs |
| `windows/` | The Windows release: its README, the NSIS installer script (per user, no administrator), the .exe's manifest (UTF-8 paths, per-monitor DPI), resource script and icon (`tools/app_icon.py`); `src/core/desktop_win.c` is its desktop (the ROM in Windows' file dialog and Downloads) and `src/core/compat.h` what differs from POSIX |
| `android/` | The Android app (`build.py android`): a Gradle project whose `RomActivity` starts the game (the icon's ROMs shortcut asking for the ROMs screen), whose `RomLook` looks at what the ROMs screen's pickers chose (Android's folder picker, or the files in one picker; each `.gba` told by its game code, BN6's and BN5's checked by SHA-1 and copied into the app's files; the folder, kept read and write, looked in again at each start and given the saves' copy; `res/xml/backup_rules.xml` keeps the ROMs out of Android's backups) and whose `GameActivity` is SDL's activity running the game's C in a process of its own (`:game`, ended with the session), built by the NDK from every `src/*/*.c` (`app/jni/CMakeLists.txt`) with SDL2's own source and the GBA core; its README says how releases are signed |
| `macos/` | The macOS app: `deps.sh` (SDL2 and mGBA as universal static libraries, on a Mac), the bundle's `Info.plist`, its icon (`tools/app_icon.py`) and the .dmg's README; `build.py macos` runs only on a Mac, so CI's macOS job builds and checks it |
| `ios/` | The iPhone and iPad app (`build.py ios`, on a Mac with Xcode): its README (AltStore and SideStore, the ROM through Files, building), `deps.sh` (SDL2 and mGBA as static arm64 libraries for the phone or the Simulator), the bundle's `Info.plist` and its icons (`tools/app_icon.py`). `src/core/ios.m` is UIKit's (the Files pickers for the ROM folder or files and the folder's looks at each start, haptics, the safe area, the `main` that hands SDL's to UIKit), `src/core/ios_saves.m` SAVES' pickers and the saves' copy in a folder; `tools/altstore_source.py` writes the AltStore source each release carries. CI's ios job builds the IPA and starts the Simulator's app |
| `3ds/` | The Nintendo 3DS build (`build.py 3ds`, issue #9): its README (playing, building, testing on a 3DS), the icon, the CIA's title settings (`cia.rsf`, for makerom) and the HOME Menu's banner (`banner.png`, `tools/steam_art.py`; its sound a few seconds of the current trailer's music, `tools/trailer_music.py --banner`). `src/core/present_3ds.c` puts the canvas on the top screen through the GPU (citro2d), and the second screen on the bottom one (`src/second/`, drawn by `platform.c` every tenth frame); `src/emu/emu.c` runs the GBA core on the New 3DS's third core where the system gives one, its picture drawn on the main core (mGBA's threaded video); `src/core/start_3ds.c` splits the app's memory, gives back the ROM buffer mGBA's 3DS setup takes and never uses, and reads BN5's ROM where the heap has room for it ([The 3DS's memory](../engine/emulation/3ds-memory.md); `tools/heap3ds.py` models that heap on the host build) |
| `switch/` | The Nintendo Switch build (`build.py switch`): its README (playing, building, testing on a Switch) and the Homebrew Menu's icon (`icon.jpg`, `tools/app_icon.py`); the `.nro` carries it with its title and version (`nacptool`). `src/core/start_switch.c` brings up the sockets, sends the output to nxlink or `log.txt` and looks for the ROMs where Switch players keep them; `src/core/pads.c` maps libnx's pads by their labels; online play and the statistics go over devkitPro's libcurl on the console's own TLS (`src/online/online_stream_curl.c`, shared with the 3DS) |
| `vita/` | The PlayStation Vita build (`build.py vita`): its README (playing, building, testing on a Vita), the bubble (`icon0.png`, `tools/app_icon.py`) and the LiveArea (`bg.png` and `startup.png`, `tools/steam_art.py`; `template.xml`), which the VPK carries with its `param.sfo` (title ID `CWEN00001`). `src/core/start_vita.c` sets its heap, stack, clocks and network and looks for the ROMs where Vita players keep them; `src/emu/emu.c` runs the GBA core on a core of its own there; `src/core/platform.c` names SDL's GXM renderer; online play and the statistics go over VitaSDK's libcurl with OpenSSL (`src/online/online_stream_curl.c`, shared with the 3DS and the Switch) |
| `ps4/` | The PS4 build, a PS5's too (`build.py ps4`): its README (playing, building, testing on a PS4), the home screen's icon (`icon0.png`, `tools/app_icon.py`) and the fake PKG's project (`pkg.gp4`), which `PkgTool.Core` packs with the eboot and its `param.sfo`. It builds against the OpenOrbis toolchain's SDL 2.0.9 (`src/core/sdl_old.h` stands in for what it lacks); `src/core/start_ps4.c` sets its folders and ROM places; online play goes over BSD sockets and mbedTLS (`src/online/online_stream_tls.c`), the SDK having no libcurl |
| `ps5/` | The PS5's own build (`build.py ps5`): its README (playing, building, submitting to Prospero Store, testing on a PS5), `param.json` (title ID `CWEN00001`, its contentVersion filled from the version) and the icon (`icon0.png`, `tools/app_icon.py`). drakmor's ps5-native-app-boilerplate (GPL-3.0, pinned) gives the CRT, linker script, ELF converter, FSELF signer and clean-room `libc.prx`; the Makefile lays out `CWEN00001/` and zips it. `src/core/ps5_libc.c` gives what the native runtime lacks of the C library; online play and the statistics go over PacBrew's libcurl (`src/online/online_stream_curl.c`) |
| `docker/` | Build images: `Dockerfile` (host, Debian trixie), `Dockerfile.portmaster` (the PortMaster port's aarch64 binary: Debian bullseye's glibc 2.31 and SDL2 2.0.14, older than any firmware PortMaster serves; `debian/eol` from its snapshot), `Dockerfile.linux` (desktop release, bookworm, SDL2 from source), `Dockerfile.windows` (MinGW-w64, SDL2 and mGBA static, NSIS), `Dockerfile.android` (the SDK, NDK and Gradle, SDL2's source, mGBA per ABI), `Dockerfile.web` (Emscripten, mGBA without threads), `Dockerfile.3ds` (devkitPro's devkitARM, SDL2 and mGBA's library for the 3DS, makerom and bannertool from their sources for the CIA: `ctrtools.sh`), `Dockerfile.switch` (devkitPro's devkitA64 with libnx, its SDL2 and libcurl, and mGBA's library for the Switch), `Dockerfile.vita` (VitaSDK with its SDL2 and libcurl, and mGBA's library for the Vita), `Dockerfile.ps4` (the OpenOrbis toolchain, and mbedTLS and mGBA's library built for it through `ps4.cmake`: `mbedtls.sh`), `Dockerfile.ps5` (the native-app template's pipeline, the PS5 payload SDK and PacBrew's SDL2 and libcurl, and mGBA's library through `ps5.cmake`), `Dockerfile.music` (the trailers' music when a piece plays a soundfont: Debian's FluidR3 GM, MIT, never in git; `tools/trailer_soundfont.py` reads it, `tools/trailer_music.py`'s render_any runs a piece there) |
| `.github/` | CI (`ci.yml`: checks, every target, Pages from `main`), releases (`release.yml`, on `v*` tags), the cached image build action, Dependabot |
