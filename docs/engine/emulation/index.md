# Running the game's own logic

* [Running the game's own logic](overview.md) - How BN6's own code runs from the player's ROM on an embedded mGBA core, the engine directing it: why an emulator, the memory it writes, hooks, layers, boot, threads, time, sound and testing.
* [The browser's memory](browser-memory.md) - The browser build's WebAssembly memory, from 64 MB at the title to about 133 MB in a run with BN5's ROM, measured in headless Chrome; some 27 MB less since the guest core left runs.
* [The core's time](time.md) - Where the GBA core's time goes, measured (issue #35): the picture, BN6's busy wait for VBlank halted by the idle hook (`src/emu/idle.c`, about 30% less), and why no routine is done in C.
* [The core on its own thread](thread.md) - The GBA core on its own thread on the New 3DS (`emu_threaded`, `CYBERWORLD_EMU_THREAD=1`): `emu_frame` starts a frame and returns, every other access waits for it, and mGBA's threaded video draws alongside.
* [Testing](testing.md) - Testing the engine against the game: the autopilot (`CYBERWORLD_AUTOPILOT`, weak), debug output, battle traces for `tools/xcontrol.py`'s byte-by-byte control family, `tools/xfamily.py`'s CanGard checks and `tools/xdiff.py`'s differential.
* [Why an emulator](why-an-emulator.md) - Why BN6 runs on mGBA rather than as a native port like Ship of Harkinian or Zelda64Recomp: no C decompilation, no display list, no shipping Capcom's code, other ROMs as data, free save states.
* [The engine's own sound](engine-sound.md) - The engine's own MP2K (`src/audio/mp2k*.c`, `gba_sound.c`): BN6's sound engine rewritten in C for the title and PET screens, proved byte for byte against the game by `tools/mp2k_verify.py`, and BN5's songs on it.
* [Fast forward](fast-forward.md) - Fast forward's frame batches in `scene_emu.c`: where BN6's state allows it (`fast_forward_game.c`, never the Custom screen or a fight), the 10 ms budget, sound kept at pitch by crossfaded grains, run time in game frames.
* [The 3DS's memory](3ds-memory.md) - How the New 3DS's 96 MB heap holds BN6's ROM, the core's 16 MB copy and BN5's (`src/core/start_3ds.c`), mGBA's ROM buffer given back, one area's learned maps kept, measured by `tools/heap3ds.py`.
* [A new run and boot](boot.md) - NEW GAME's start in the town (first layer built, Lan warped to his start, jack-in flag 0x1727 cleared) and `emu_boot`, which presses through BN6's title to Seaside Area 1 and saves `boot-3.state`.
* [Hooks](hooks.md) - Hooks on BN6's code (`src/emu/hook.c`): a BKPT over an instruction that calls the engine's C mid-frame, event and answer hooks, one table per core, and every address hooked, from battles and maps to BN5's Souls.
* [Memory the engine writes](memory.md) - The free space plan for the core's ROM copy past BN6's 8 MB, region by region from `EMU_FREE` (`src/emu/free_space.h`, `claims.c`), BN6's tables patched in place, and the EWRAM BN6 leaves alone (`RAM_*`).
* [The core's sound](core-sound.md) - How the core's sound reaches the device: `audio_pace.c` nudges mGBA's resampling by the ring's averaged fill, settings.ini's `sound` filters it, and a hook on TrkVolPitSet (`sound_quiet.c`) silences music or effects.
* [A layer](layer.md) - How a layer is built into the game (`net_gen.c`, `netmap.c`, `layer_objs.c`, `mapslot.c`), its exit pad's warp, what `director.c` watches, checkpoints and CONTINUE, the engine's event flags and `talk.c`'s conversations.
