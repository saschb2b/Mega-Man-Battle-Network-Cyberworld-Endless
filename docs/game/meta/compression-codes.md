# Compression codes, kept once entered (3 October 2026; applied, 23 October 2026)

BN6 compresses a NaviCust program by a code of ten buttons, entered on the
NaviCust screen with RIGHT held on it (its table at ROM `0x13D302`; the
code sets the event flags of the program's four colours, `0x2660` +
variant, and entered again clears them, [ROM data](../../rom/overview.md)). The game never
says them, and a run, a fresh game, forgets every compression: a player
looked the codes up again for every run (issue #50). The owner chose
then, of three ways reasoned with the game-design skill (kept once
entered, kept and also found on the net, all known from the start),
**kept once entered**, the buttons still pressed by hand in every run.

A player asked for more: "Once you've entered a compression code for a
program, it should automatically apply in future runs. It's hard to
remember all the codes, so I usually end up not using them." The owner
asked for it (23 October 2026), and of the ways reasoned again (the
program compressed from the run's start, one press on it in BN6's
NaviCust screen, the buttons as before), a known code is now **applied
as every run begins**:

- **The dialectic** is still the NaviCust's, fit it or force it:
  compression fits more in the board's budget, at the price of knowing
  the code. Knowing stays the meta layer's progress, and the price is
  paid once, by entering the code in some run.
- **The press was no decision:** every compressed shape is a part of its
  full one, cell for cell (the 64 colour variants with a compressed shape
  read from the ROM's records: SuperArmor 7 blocks to 4, Custom1 6 to 4),
  so wherever a program fits whole it fits compressed. A program compressed is never worse, and pressing ten
  buttons for it each run was a chore with nothing to weigh. The skill's
  rule on conveniences, that each deletes a decision, holds only where
  there was one, and the player's own words name the cost of the chore:
  the codes went unused.
- **Why not one press:** a shortcut on BN6's NaviCust screen would patch
  its input with a rule of ours to learn, for a choice that is still none.
- **Knowledge, not power:** the codes are public; what carries over is what
  the player has found, as before. A code never entered is never applied,
  never named (the secret stays one), and the rumor of a secret pattern of
  buttons is told until the first is entered (Rumors). The week's net
  starts from a standard profile with none ([Online: the Net Square](../../online/overview.md)).
- **How it shows:** as a run begins, the flags of each known program's
  four colours are set as BN6's own code input sets them (not on a program
  placed on the board, which a fresh game has none of), so the NaviCust
  lists it compressed from the first time it is held. The player's choice
  stays BN6's: entered again, the code undoes it for that run, and a
  CONTINUE keeps the flags as the player left them (they are the game's,
  in its state). The first time a code is entered in any run, MegaMan says
  so ("Dad's lab will compress it for us every dive now!"); Dad's
  Compression mail lists every program it compresses with its code
  ([The PET](../pet.md)), NEW with each new one, so a code stays there to look up.
- **What could go wrong:** a profile from before has its codes compressed
  at the next run without a word, but for the mail's first line; the
  planned NaviCust workshop ([The NaviCust](../navicust.md), 4) sells compression, and
  with codes applied its part is to compress a program the first time, and
  so teach its code.
