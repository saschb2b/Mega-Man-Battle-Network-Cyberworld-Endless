# ROM data

All offsets are for Mega Man Battle Network 6: Cybeast Gregar (USA), SHA-1
`89fe0bac4fd3d2ab1d2ca35e87ef8b1294a84cd6`, and live in `RomLayout` in
`src/core/rom.c`. The [bn6f disassembly](https://github.com/dism-exe/bn6f)
targets Cybeast Falzar; most code-region tables sit at the same addresses in
Gregar, and the rest were found by searching the Gregar ROM for the
structures the disassembly describes. `tools/romlab` runs the ROM in libmgba
to confirm findings against real frames and VRAM.

| Data | Offset | How it was found / verified |
| --- | --- | --- |
| Sprite pointer lists | `0x031CC4` | Ten pointers, the first pointing just past the list (`SpritePointersList`). Every category renders correctly. |
| Chip records (0x2C bytes) | `0x021DA8` | Same address as Falzar's `ChipDataArr`. Cannon = 40 power, codes A B C *. |
| Chip names | `0x6E88D0`, `0x6E92D8` | Text archives found by encoding "Cannon" with the game's character table; pointers in code reference both. |
| Enemy id table | `0x0182C4` | `GetVerActorTyAndAIIdx`: (version, actor type, AI index) triples. |
| Font | `0x6B5A2C` | 8x16 glyphs indexed by character code (the battle font); the run summary uses it. |
| Title screen | `RomLayout.title`; load table at `0x02FCD8` | The game's own load list (source, VRAM or palette-buffer destination, size) gives the LZ77 blocks: the 256-colour picture's tiles `0x7F3040` (to 0x06000000), PRESS START / NEW GAME / CONTINUE `0x7F1EBC` (OBJ tile 1 on) with palettes `0x7F216C` and `0x7F218C`, and the copyright line `0x7F21EC` (8 OBJs of 32x32, palette `0x7F2C20`). The picture's 32x20 map sits at `0x7F7CFC`, its palette at `0x7F2E40` (banks 0-13, bank 15 the text box's `0x6BCBCC`), and the logo's glow is six palette scripts listed at `0x02F5F0`. The menu arrow is 3 frames at `0x6A280C` (palette `0x6A344C`). Positions and timing came from recorded OAM and palette RAM: PRESS START blinks 32/32, START (sound 0x67) dims every colour by 4 then 2 a frame to 16 and the menu follows 84 frames later; NEW GAME plays 0x9D, CONTINUE 0x9C, and the music stops. |
| Boot and warps (`src/emu/boot.c`) | `0x02009CD0` eChatbox, `0x02009F38` its flags, `0x02011BB0` Warp2011bb0, `0x02011C50` CutsceneState, `0x08005C05` map_triggerEnterMapOnWarp, `0x080050EC` cbGameState | The engine's warp copies a warp record into Warp2011bb0 and calls the game's own warp routine from a stub in the free ROM space, borrowing cbGameState (run every frame of the game mode) for one frame; the overworld routine at `0x08005A8C` it borrowed before does not run on every map frame. After NEW GAME it warps to Seaside Area 1 and ends the intro by clearing the cutscene script and closing the chat box as the chat script's end command (E6) does. Found in the bn6f disassembly and tested in `tools/romlab`. |
| Encounter roll (`src/emu/encounter.c`) | `0x0ABD30` | Returns the `BattleSettings` record (bn6f `battle_settings_struct`, 16 bytes: field, music, type, background, side modifier, options, entity list pointer) for a random battle. The engine moves its first 12 bytes (position independent) into a trampoline and wraps it, so the game's own step counter and chance still decide when a battle happens and only a non-NULL result is swapped for the engine's record in the free ROM space. Entity entries are kind (0x00 MegaMan, 0x11 enemy), panel (row << 4 \| column, from 1) and the enemy id, ending with 0xF0. |
| Map takeover (`src/emu/mapslot.c`) | `0x0347E0` NPCList_maps80, `0x034670` map scripts, `0x03483C` object spawners, `0x0A484C` Mystery Data groups, `0x02004348` Mystery Data picks | Per group (index group − 0x80; the internet is 0x90-0x96) the engine points the layer's map at its own NPC list, empty map scripts and objects, and its Mystery Data (12-byte entries: type 5 green or 1 blue, flag 0x1400+n, one placement `[1, 0x20, X, Y, Z]`, one content `[kind, 0x20, 0xFF, code, value]`; kinds 1 chip, 3 zenny, 4 key item, 5 BugFrags). The object table is the literal of the spawner's first `ldr r1, [pc]`. |
| Map sprite lists (`src/emu/mapslot.c`) | `0x03093C` EnterMap_InternetMapGroupJumptable | Each group's loader passes a per-map list of `(0x1C, sprite)` pairs ending `0xFFFF` to uncompSprite; compressed overworld objects (pointer bit 31, like the Chip Trader 0x5C) only draw once listed. The table is the literal of the loader's `lsl r1, r1, #2; ldr r0, [pc]; ldr r0, [r0, r1]`; the engine replaces the map's list with the layer's own objects (the original's would fill the decompression buffer). |
| NPC and text scripts (`src/emu/npc.c`, `text.c`) | charmap and commands per bn6f `text_script_commands.inc` | NPCs are bn6f NPC bytecode (0x08 visible, 0x25 sprite `index, category * 4`, 0x14 position, 0x16 animation, 0x44 text script and archive, 0x10 pause, 0x02 jump). Layer dialogue is a text archive (u16 offsets, then scripts) using E8 open, E7 wait, F2 clear, E6 end, FC 03 13 full HP, FB 05 shop, FB 06 01 BugFrag trader, FB 06 03 Chip Trader. |
| Shops (`src/emu/shop.c`) | `0x046B68` shop descriptors, `0x047D70` initial shop data, eToolkit+0x54 ShopDataPtr | A descriptor is 16 bytes: currency (0 zenny, 1 BugFrags, 2 Chip Order), keeper text, offset into the shop data, entries. Entries are 8 bytes: kind (1 item: 0x70 HPMemory, 0x80+ SubChips; 2 chip; 3 NaviCust program), stock (0xFF unlimited), u16 id, code (program color), 0, u16 price in hundreds. The shop screen lists only entries that match the ROM's initial data, so layers write their stock to both; shops 0 and 1 are taken over. Traced in `tools/romlab`. |
| Key items (`src/emu/director.c`) | eToolkit+0x50 KeyItemsPtr (`0x02003134`), checks at `0x020004E0` and eToolkit+0x78 | One count per key item id; `CheckKeyItem` returns 0 unless byte id of the first check XOR 0x55 equals byte id of the second, which the game sets when it gives the item. ScrtData is key item 0x31 (the key item name archive); a blue Mystery Data with content `[4, 0x20, 0xFF, 0xFF, 0x31]` gives one, and the Secret Area gate checks three with `ts_check_item07`. |
| Net maps (`src/emu/area_src.c`, `netmap.c`) | `0x0329C4` map descriptors, `0x03354C` coordinate data, `RomLayout.net_area[]` | One pointer per map group (0x80 first) to 12-byte descriptors per map: a tile set (two headers of word count, offset to LZ77 data and VRAM offset), a palette (a 4-byte size, then 16 banks) and a tile map (width, height, 0, 0, u32 12, u32 offset of layer 2 in the decompressed data, then LZ77). Coordinate data is a 16-byte header of four section offsets and LZ77; section 0 lists wall cells (8x8 world units, key (y+127)*254+(x+127)) with 4-byte shapes (lowest z, flag, height, type 1-8). Each biome learns its tiles from one map (Central 0x90:0, Seaside 0x91:0, Sky 0x94:1, Green 0x92:0, Graveyard 0x96:1, Undernet 0x95:0, Undernet Zero 0x95:1, Underground 0x93:1): tiles are classed by their place in a 32x32 panel and the floor around it, keeping panels whose middle has the listed hue (`styles`, 12 buckets plus grey). Undernet-style maps draw their static in the back tile layer, so only the front layer marks floor there (`bg_in_map`). |
| MP2K song table | `0x159F48` | Longest run of valid song headers (474 entries). Song and effect ids follow the disassembly's `SoundOffsets.inc`. |
| MP2K player table | `0x159DC8` | 32 entries of (`MusicPlayerInfo`, tracks, count) ending at the song table; player 31 is music. Used to log sounds in recordings. |
