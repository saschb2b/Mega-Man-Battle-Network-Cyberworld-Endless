# ROM data

All offsets are for Mega Man Battle Network 6: Cybeast Gregar (USA), SHA-1
`89fe0bac4fd3d2ab1d2ca35e87ef8b1294a84cd6`, and live in `RomLayout` in
`src/core/rom.c`. The [bn6f disassembly](https://github.com/dism-exe/bn6f)
targets Cybeast Falzar; most code-region tables sit at the same addresses in
Gregar, and the rest were found by searching the Gregar ROM for the
structures the disassembly describes. `tools/romlab` runs the ROM in libmgba
to confirm findings against real frames and VRAM.

| Data | Offset | How it was found / verified |
| --- | --- | --- |
| Sprite pointer lists | `0x031CC4` | Ten pointers, the first pointing just past the list (`SpritePointersList`). Every category renders correctly. |
| Chip records (0x2C bytes) | `0x021DA8` | Same address as Falzar's `ChipDataArr`. Cannon = 40 power, codes A B C *. Codes at 0, rarity 0-4 at 5, library type at 7 (0 standard, 1 Mega, 2 Giga, 3 secret, 4 Program Advance), library number at 0x15, library flags at 0x16 (bit 0: the other version's Navi chips and Otenko; 0x30: unused arm and dark chips; 0x10 alone: the Beast chips). A run can find or buy 283 of them (`src/core/chip_pool.c`): standard 1-202, the Megas 221-277 but Falzar's Navis, the ten Gigas 301-310. Records 203-220 are blank, 315 on pseudo-chips. |
| Chip names | `0x6E88D0`, `0x6E92D8` | Text archives found by encoding "Cannon" with the game's character table; pointers in code reference both. |
| Enemy id table | `0x0182C4` | `GetVerActorTyAndAIIdx`: (version, actor type, AI index) triples. |
| Font | `0x6B5A2C` | 8x16 glyphs indexed by character code (the battle font); the run summary uses it. |
| Title screen | `RomLayout.title`; load table at `0x02FCD8` | The game's own load list (source, VRAM or palette-buffer destination, size) gives the LZ77 blocks: the 256-colour picture's tiles `0x7F3040` (to 0x06000000), PRESS START / NEW GAME / CONTINUE `0x7F1EBC` (OBJ tile 1 on) with palettes `0x7F216C` and `0x7F218C`, and the copyright line `0x7F21EC` (8 OBJs of 32x32, palette `0x7F2C20`). The picture's 32x20 map sits at `0x7F7CFC`, its palette at `0x7F2E40` (banks 0-13, bank 15 the text box's `0x6BCBCC`), and the logo's glow is six palette scripts listed at `0x02F5F0`. The menu arrow is 3 frames at `0x6A280C` (palette `0x6A344C`). Positions and timing came from recorded OAM and palette RAM: PRESS START blinks 32/32, START (sound 0x67) dims every colour by 4 then 2 a frame to 16 and the menu follows 84 frames later; NEW GAME plays 0x9D, CONTINUE 0x9C, and the music stops. |
| Boot and warps (`src/emu/boot.c`) | `0x02009CD0` eChatbox, `0x02009F38` its flags, `0x02011BB0` Warp2011bb0, `0x02011C50` CutsceneState, `0x08005C05` map_triggerEnterMapOnWarp, `0x080050EC` cbGameState | The engine's warp copies a warp record into Warp2011bb0 and calls the game's own warp routine from a stub in the free ROM space, borrowing cbGameState (run every frame of the game mode) for one frame; the overworld routine at `0x08005A8C` it borrowed before does not run on every map frame. After NEW GAME it warps to Seaside Area 1 and ends the intro by clearing the cutscene script and closing the chat box as the chat script's end command (E6) does. Found in the bn6f disassembly and tested in `tools/romlab`. |
| Encounter roll (`src/director/encounter.c`) | `0x0ABD30` | Returns the `BattleSettings` record (bn6f `battle_settings_struct`, 16 bytes: field, music, type, background, side modifier, options, entity list pointer) for a random battle. The engine moves its first 12 bytes (position independent) into a trampoline and wraps it, so the game's own step counter and chance still decide when a battle happens and only a non-NULL result is swapped for the engine's record in the free ROM space. Entity entries are kind (0x00 MegaMan, 0x11 enemy), panel (row << 4 \| column, from 1) and the enemy id, ending with 0xF0. |
| Random battles (`src/core/formations.c`) | `0x020170` four story-stage tables | Each table holds two pointers, real world and internet; the internet one lists per map group (from 0x80) per map a run of 16-byte BattleSettings ending with 0xFF (bn6f `sub_80AA5F4`). Byte 0 is the battlefield (the panels' layout: grass, holes, ice, poison...), bytes 12-15 the entity list. Every internet map has 10-50 of them: Central's Mettaur, Swordy, Quaker, Champy, Trumpy, OldStov, Gunner, Armadill; Seaside's Piranha, Puffy, StarFish; Green's BombCorn, HonyBmbr, Armadill; Sky's ScarCrow, FgtrPlne, Catack; Undernet's BigHat, SnakeArm, PulsBulb, DarkMech, Shrubby, Cragger; Graveyard and Underground most of the 29 families, with ErthDrgn and Nghtmare; each area also hides a rare pair and one SP navi. An area fights the formations of its maps (`RomLayout.net_area[].battles`), weighted by how many tables list them. The virus names archive (`TextScriptVirusChipNames`) is indexed by the enemy id of `0x0182C4`. |
| Map takeover (`src/map/mapslot.c`) | `0x0347E0` NPCList_maps80, `0x034670` map scripts, `0x03483C` object spawners, `0x0A484C` Mystery Data groups, `0x02004348` Mystery Data picks | Per group (index group − 0x80; the internet is 0x90-0x96) the engine points the layer's map at its own NPC list, empty map scripts and objects, and its Mystery Data (12-byte entries: type 5 green or 1 blue, flag 0x1400+n, one placement `[1, 0x20, X, Y, Z]`, one content `[kind, 0x20, 0xFF, code, value]`; kinds 1 chip, 3 zenny, 4 key item, 5 BugFrags). The object table is the literal of the spawner's first `ldr r1, [pc]`. |
| Map sprite lists (`src/map/mapslot.c`) | `0x03093C` EnterMap_InternetMapGroupJumptable | Each group's loader passes a per-map list of `(0x1C, sprite)` pairs ending `0xFFFF` to uncompSprite; compressed overworld objects (pointer bit 31, like the Chip Trader 0x5C) only draw once listed. The table is the literal of the loader's `lsl r1, r1, #2; ldr r0, [pc]; ldr r0, [r0, r1]`; the engine replaces the map's list with the layer's own objects (the original's would fill the decompression buffer). |
| NPC and text scripts (`src/layer/npc.c`, `text.c`) | charmap and commands per bn6f `text_script_commands.inc` | NPCs are bn6f NPC bytecode (0x08 visible, 0x25 sprite `index, category * 4`, 0x14 position, 0x16 animation, 0x44 text script and archive, 0x10 pause, 0x02 jump). Layer dialogue is a text archive (u16 offsets, then scripts) using E8 open, E7 wait, F2 clear, E6 end, FC 03 13 full HP, FB 05 shop, FB 06 01 BugFrag trader, FB 06 03 Chip Trader. NPC command 0x13 keeps an object from turning to MegaMan when spoken to; objects have no such frames and would vanish. |
| Chip Traders (`src/layer/trader.c`) | `0x086C3758` TextScriptChipTrader, `0x0804CDE0` prize pools, `0x0809B7E4` trader kinds | The trader archive is stored uncompressed; script 0 is the Chip Trader (3 chips), 6 the Chip Trader Special (10), 12 the BugFrag Trader, each with the game's Yes/No, not-enough lines and "Try again?". The trade screen (`selectChipTraderRewardList`, Gregar `0x0804CDB4`) looks the current map (group << 8 \| number) up in five 12-byte entries (map key, chip list of 6-byte records ending with 0, weights per rarity): 0x104 70 chips of rarity 1-3, 0x501 130 of 1-4, 0x000 108 of 1-3, 0x400 163 mostly 3-4, 0x9301 60 of 3-5 for BugFrags. With no match it returns no list and draws garbage prizes. `0x0809B7BC` looks the map up in six 8-byte entries (map key, byte) for the trader's script, which picks the lines the screen shows; with no match it takes the map number. Each layer rewrites the first entry of both tables with its own map. Falzar's tables are at `0x0804C01C` and in `asm03_2.s`. |
| Floor sprites (`src/layer/npc.c`) | NPC commands `0x1B`, `0x0C` | Overworld sprites share MegaMan's layer priority, which coordinate data section 2 sets per position (`checkLayerPriority_80318b0`), and the game orders them in OAM front to back by depth. `ns_set_layer_priority_override_to_3` puts a pad at priority 3, under MegaMan and over the floor layers. That alone fails from behind: between sprites the GBA draws the earlier OAM entry whatever their priority bits, so a pad sorted in front of MegaMan took the pixels over his feet and then lost them to the floor layer. Pads therefore stand 64 units further back in depth (+X, -Y) and 64 lower, which draws them in the same place but sorts them after MegaMan, and `ns_shift_center` (x, y, z signed bytes, stored in the object's CenterOffsetX/Y/Z) moves their collision and talk centre back to the pad. |
| Shops (`src/layer/shop.c`) | `0x046B68` shop descriptors, `0x047D70` initial shop data, eToolkit+0x54 ShopDataPtr | A descriptor is 16 bytes: currency (0 zenny, 1 BugFrags, 2 Chip Order), keeper text, offset into the shop data, entries. Entries are 8 bytes: kind (1 item: 0x70 HPMemory, 0x80+ SubChips; 2 chip; 3 NaviCust program), stock (0xFF unlimited), u16 id, code (program color), 0, u16 price in hundreds. The shop screen lists only entries that match the ROM's initial data, so layers write their stock to both; shops 0 and 1 are taken over. Traced in `tools/romlab`. |
| Key items (`src/director/director.c`) | eToolkit+0x50 KeyItemsPtr (`0x02003134`), checks at `0x020004E0` and eToolkit+0x78 | One count per key item id; `CheckKeyItem` returns 0 unless byte id of the first check XOR 0x55 equals byte id of the second, which the game sets when it gives the item. ScrtData is key item 0x31 (the key item name archive); a blue Mystery Data with content `[4, 0x20, 0xFF, 0xFF, 0x31]` gives one, and the Secret Area gate checks three with `ts_check_item07`. |
| Map music (`src/map/mapslot.c`) | `0x0360E4` (3 chapter lists), GameState+0x0F BGMusicIndicator, music player `0x02010890` | `playCertainMapMusicBasedOnEventByte` (`0x08036E44`) picks the list by GameState+7 and finds (group, per-map song bytes) entries of 8 bytes ending 0xFF; a missing group plays 0x63 (none). At the boot state's chapter only Central has a song, so the engine points every list at one holding the layer's map. `PlayMusic` skips the song in BGMusicIndicator, so a warp clears it while the music player's status has bit 31 (stopped). Area themes: Central 0x13, Seaside 0x11, Sky 0x0A, Green 0x12, Graveyard 0x09, Undernet 0x14, Undernet Zero 0x20, Underground 0x21. |
| Run locks (`src/director/director.c`) | event flags `0x1727`, `0x1706` | The jack routine (`0x08034CB6`) returns before jacking in or out while `0x1727` is set; `0x1706` (EVENT_PET_COMM_SAVE_DISABLED) makes the PET's Comm and Save buzz (`SOUND_CANT_JACK_IN`). Both are set on every layer and after CONTINUE. |
| Crosses and Beast Out (`src/director/powers.c`) | event flags `0xE0`, `0xE2`-`0xE6` | Found by setting ranges of event flags before a forced battle and halving them until CROSSSELECT appeared: `0xE2` HeatCross, `0xE3` ElecCross, `0xE4` SlashCross, `0xE5` EraseCross, `0xE6` ChargeCross. `0xE0` adds Beast Out (the emblem under OK and its counter); `sub_801D814` (`0x0801D814`) reads it, and `0x163` switches it off again. |
| Messages from the engine (`src/director/director.c`) | `0x08040358` chatbox_runScript (archive, script) | Found by its prologue (it saves the chat box fields 0x4C-0x58 around a clear). Run through `game_call`, it opens the chat box over the net and holds MegaMan until it closes, as map scripts do. |
| Navi overworld sprites (`src/layer/layer_objs.c`) | sprite list 6: `0x47` HeatMan, `0x49` ElecMan, `0x4B` SlashMan, `0x50` EraseMan, `0x4F` ChargeMan, `0x3B` ProtoMan, `0x52` DiveMan, `0x55` JudgeMan | Rendered with `--sheet @6:0x38:40` and matched to the battle sprites (list 0, `0x2F`-`0x3E`). The Falzar Navis' entries point at the placeholder dot; guardians without a sprite take HeelNavi's (`0x43`). A guardian's NPC script leaves with `ns_jump_if_flag_set` (0x04) to `ns_free_and_end` once the engine sets its flag. |
| Warp pads (`src/map/coords.c`, `mapslot.c`) | coordinate data section 3, warp lists per group (first `ldr r0, [pc]` literal of each EnterMapGroup, e.g. `0x08072410` for Central), `0x02011BB0` Warp2011bb0, event flags `0x16F0`+n | Section 3 has the walls' format; a pad is 3x3 cells with shape `[z, warp index, height, type]`, types 9-C at the corners and 0x11 elsewhere (Central Area 1's own pads). `0x080058D0` checks the trigger under MegaMan each frame on the map: index 1-15 unless flag `0x16F0`+index is set, then sets Warp2011bb0 +0x10 to 1 and +0x11 to the index and runs the entry's departure (byte 2 of the 16-byte WarpData: group, number, departure, facing, x, y, z; 8 is the jack-out cutscene). The game clears the `0x16F0` flags when it enters a map. |
| Net maps (`src/map/area_src.c`, `netmap.c`) | `0x0329C4` map descriptors, `0x03354C` coordinate data, `RomLayout.net_area[]` | One pointer per map group (0x80 first) to 12-byte descriptors per map: a tile set (two headers of word count, offset to LZ77 data and VRAM offset), a palette (a 4-byte size, then 16 banks) and a tile map (width, height, 0, 0, u32 12, u32 offset of layer 2 in the decompressed data, then LZ77). Coordinate data is a 16-byte header of four section offsets and LZ77; section 0 lists wall cells (8x8 world units, key (y+127)*254+(x+127)) with 4-byte shapes (lowest z, flag, height, type 1-8). Each biome learns its tiles from one map (Central 0x90:0, Seaside 0x91:0, Sky 0x94:1, Green 0x92:0, Graveyard 0x96:1, Undernet 0x95:0, Undernet Zero 0x95:1, Underground 0x93:1): tiles are classed by their place in a 32x32 panel and the floor around it, keeping panels whose middle has the listed hue (`styles`, 12 buckets plus grey); walkways learn from the panels of a second hue (`walk_styles`: Central 6, Seaside 1-2, Sky 6 and 8, Green 0, Graveyard 8, Undernet 10-11). Undernet-style maps draw their static in the back tile layer, so only the front layer marks floor there and their back-layer entries are not copied (`bg_in_map`). Every map draws its floor 3-4 pixels below the panel edges its walls give, with side faces about 9 pixels tall under the bottom edges; `tiles.c` measures both per map for its pixel test. |
| Height (`src/map/stairs.c`, `netmap.c`, `coords.c`) | coordinate data sections 1 and 2 | Section 1 holds floor heights in the walls' format: type 0x11 raises a whole cell to z, types 0x13 (climbing towards world +X) and 0x14 (towards world -Y) are ramp cells with the foot's z, value 1 and the height above it, rising 4 per cell. Section 2 marks cells of each level for sprite priority (type 0x11, height 8). Walls beside a ramp or around a raised floor start at the ground and are taller (32 around Seaside's 16-high platform, 42 beside Sky's 32-high stair); a ramp's top meets its raised floor with no wall. |
| MP2K song table | `0x159F48` | Longest run of valid song headers (474 entries). Song and effect ids follow the disassembly's `SoundOffsets.inc`. |
| MP2K player table | `0x159DC8` | 32 entries of (`MusicPlayerInfo`, tracks, count) ending at the song table; player 31 is music. Used to log sounds in recordings. |
